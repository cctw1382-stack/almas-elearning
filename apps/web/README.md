# واجهة الماس — المرحلة الثانية

واجهة قابلة للبناء على Vite مع أساس PWA محلي. التصميم والأدوار الأربعة من النموذج المعتمد. الدخول والاشتراكات والرسائل بيانات تجريبية محلية، وليست خدمات إنتاجية.

## التشغيل

من جذر المستودع:

```sh
npm ci --prefix apps/web --ignore-scripts
npm run build:web
npm run preview:web
```

افتح http://127.0.0.1:4174/ . تتطلب الأدوات Node ^20.19.0 أو >=22.12.0؛ التحقق المحلي جرى على 22.23.2. للتطوير فقط: `npm --prefix apps/web run dev`؛ اختبر PWA على المعاينة المبنية، لا خادم التطوير.

## العمل دون إنترنت والتحديث

- الزيارة الأولى تحتاج اتصالاً. بعد اكتمال التجهيز يمكن إعادة فتح الواجهة دون إنترنت.
- لا يخزن Service Worker إلا HTML وCSS وJavaScript والأيقونات وmanifest الموجودة في البناء. لا يضيف استجابات الحسابات أو ملفات الفيديو أو طلبات أخرى إلى الكاش.
- نسخة جديدة تنتظر اختيار «تحديث الآن». «لاحقاً» يبقي المسودة، وتحديث تبويب آخر لا يعيد تحميل تبويبك تلقائياً. احفظ نموذجك أولاً؛ الإجابات التي حُفظت محلياً تبقى بعد التحديث، لكن نصاً لم تحفظه سيضيع عند إعادة التحميل التي توافق عليها.
- فشل تنزيل إصدار جديد يبقي الإصدار السابق متاحاً. حذف بيانات الموقع يحذف البيانات التجريبية والكاش.
- التخزين مرتبط بالعنوان والمتصفح. تبديل المنفذ أو الانتقال من عنوان الشبكة إلى localhost ينشئ مساحة تخزين أخرى؛ ليس ترحيلاً تلقائياً لبيانات جهاز آخر.
- تثبيت التطبيق يعتمد على دعم المتصفح وHTTPS أو localhost. معاينة الهاتف عبر HTTP على الشبكة لا تثبت التثبيت أو offline على الجهاز.
- ملفات الفيديو المختارة لا تُحفظ؛ يلزم اختيارها مجدداً بعد إعادة فتح الصفحة.

المعاينة تعرض ملفات البناء المسموح بها فقط. يمكن فتحها للشبكة المحلية المأذونة: `node apps/web/scripts/preview.mjs --host 0.0.0.0 --port 4174`. لا تستخدم خادم التطوير Vite لهذا الغرض، ولا تعتبر المعاينة نشراً إنتاجياً. يجب أن تكون الاستضافة النهائية من جذر نطاق HTTPS مخصص؛ عامل الخدمة يستخدم نطاق `/`، فلا يوضع بجانب تطبيق آخر على النطاق نفسه دون تغيير النطاق والسياسة.

## التحقق والحدود

```sh
npm run test:web:unit
npm run test:web:e2e
npm run test:web:pwa
```

اختبارات المتصفح تحتاج أدوات الاختبار في الجذر والمتصفحات المثبتة. الاختبارات الحالية تستخدم ملفات البناء مباشرة. اختبارات PWA تعمل منفصلة مع Service Worker فعلي. المحاكاة تبدّل HTML ونسخة الكاش؛ لا تختبر بعد تبديل أسماء JS/CSS أو نشر خادم إنتاج.

`typecheck` صارم لوحدات TypeScript، ومنها عقد Repository والتخزين المحلي وإنشاء وتصحيح المحاولة والتحقق من JSON والسجلات وتقدم الدروس، إضافة إلى التطبيق وعامل الخدمة. `legacy.js` وعمليات المستودع المتبقية في `mock-repository.js` لا يخضعان بعد لفحص أنواع شامل. نقل Repository والعرض والأحداث واختبار Android الفعلي بنطاق المرحلة الثانية لم يكتمل بعد.

اختبارات وحدات TypeScript تستخدم دعم Node الأصلي لتجريد الأنواع؛ استخدم Node 22.13 أو أحدث ضمن سلسلة 22، كما تفعل بيئة CI. يسمح إعداد TypeScript باستيراد امتداد `.ts` مع `noEmit` حتى تشترك الاختبارات والبناء في المصدر نفسه.

قبل إدخال lazy imports يجب تعديل سياسة حذف الكاش القديم لحماية الملفات التي تحتاجها التبويبات القديمة. حالياً يُحمّل التطبيق كله مقدماً.
