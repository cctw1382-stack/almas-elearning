# عقد Go لخادم الماس

هذا المجلد يحتوي نماذج Go وربط HTTP للعمليات الست في عقد التعلم المشترك. نقطة اختبار الربط هي `httptest` مع بيانات وهمية.

من `apps/api` وبوجود Go 1.25 أو أحدث في PATH:

```sh
go generate ./...
go mod download
go mod verify
go test -count=1 -v ./...
go vet ./...
```

يولّد `go generate` الملف `internal/learningapi/learning.gen.go` من `contracts/learning.openapi.json` عبر `oapi-codegen v2.8.2`. عدّل العقد ثم أعد توليد Go وأنواع TypeScript باستخدام `npm run generate:contracts` من الجذر.

نقطة الربط هي `learningapi.NewValidatedHandler` عند `/api/v1`. تستقبل واجهة الخدمة ودالة تحقق الهوية، وتفحص الطلب وفق المخطط المضمّن قبل تمريره إلى المعالج. تقيد الجسم بـ16 KiB وتعيد أخطاء JSON بمعرف طلب. يستلم رابط Go القيمة نفسها التي تحقق منها المخطط.

مرّر نتيجة `NewKeycloakAuthenticator` إلى `NewValidatedHandler`. إعداد التطوير يستخدم مصدر النطاق المحلي، وجمهور `almas-api`، والعميل `almas-web-local`. تستخرج الخدمة الهوية الموثقة عبر `IdentityFromContext` لاستخدامها في استعلام عضوية المدرسة.

تغطي اختبارات `httptest` رفض الهوية على المسارات الستة وفحص رموز JWT الموقعة وحدود طلب حفظ الإجابة. يشغّل اختبار PKCE الاختياري Keycloak معزولاً ويختبر الرموز التي يصدرها. تبقى عضوية المدرسة ومعاملات PostgreSQL ضمن بوابات القبول. [تشغيل اختبار الهوية](../../infra/identity/README.md) و[سجل المرحلة الثالثة](../../docs/PHASE3_ACCEPTANCE_LEDGER.md).

`PostgresSessions.GetSession` ينفذ قراءة الحساب والعضويات في `GET /api/v1/session`. تستعمل الخدمة اتصال `pgxpool` لدور `almas_app` المخصص للقراءة، وتستمد هوية الطلب من سياق المصادقة. يُنشئ مالك قاعدة البيانات الدور المقيد قبل تطبيق ترحيل `0001_identity_membership.sql`. يجب أن يظل حساب الاتصال خاصاً بخادم Go لأن الخادم يضبط سياق RLS. إدخال الحسابات والعضويات يحتاج مسار إدارة موثوقاً.

لاختبار هذه الدفعة على Windows، وفّر Go على PATH وأدوات PostgreSQL في مجلد محلي. شغّل من جذر المستودع:

```powershell
pwsh -NoProfile -File infra/test-postgres-memberships.ps1 -PostgresBin 'C:\path\to\pgsql\bin' -TestRoot 'C:\path\to\almas-pg-tests'
```

ينشئ السكربت مثيل اختبار على الحلقة المحلية بمسار لاتيني، ويطبق الترحيل ويضيف بيانات وهمية ويختبرها قبل وبعد الاستعادة إلى قاعدة منفصلة في المثيل نفسه. يحتفظ بالسجل والنسخة الاحتياطية في مجلد الاختبار ويوقف المثيل. استعادة دور الاتصال في مثيل جديد تتطلب تهيئته قبل الاستعادة.

يطبق السكربت أيضاً `0002_student_exam_read.sql` ويختبر `PostgresExams.GetStudentExam`. تقرأ الخدمة أسئلة اختبار منشور للطالب المكلّف به في مدرسته. لإضافة اختبار HTTP برمز Keycloak فعلي، مرّر `-IdentityRuntimeRoot 'C:\path\to\identity-runtime'` إلى الأمر نفسه. يُشغّل ذلك نطاقاً وهمياً معزولاً بالتزامن مع قاعدة الاختبار.

يضيف `0003_exam_attempt_start.sql` و`PostgresAttempts.StartAttempt` بدء المحاولة بموعد يحدده PostgreSQL ويقف عند إغلاق الاختبار. تعيد المفاتيح المختلفة المحاولة النشطة نفسها. يعيد المفتاح نفسه حالة HTTP وجسم استجابة البدء الأصليين خلال 24 ساعة مع إعادة فحص العضوية والتكليف. تستخدم هذه الدفعة محاولة واحدة لكل تكليف حتى تُحدد سياسة الإعادة. يشمل سكربت الاختبار التزامن والتكرار والاستعادة، ويفحص تشغيل Keycloak الاختياري رفض موعد يرسله العميل في طلب البدء.

يضيف `0004_exam_answers.sql` و`PostgresAttempts.SaveAnswer` حفظ الإجابات ضمن الموعد الذي يفرضه PostgreSQL. أرسل مراجعة المحاولة الحالية مع كل كتابة. لإعادة الطلب نفسه خلال 24 ساعة، استخدم مفتاح التكرار والحمولة الأصليين. عند تعارض المراجعة أو انتهاء الموعد تعيد الخدمة 409. يختبر سكربت PostgreSQL الترحيل فوق بيانات سابقة، وتعارض المراجعات، وعزل الإجابات. يشمل تشغيل Keycloak الاختياري طلب HTTP للحفظ وإعادة الطلب.
