# المهمة

أكمل **مرحلة واحدة فقط** من منصة الماس بالكامل — كوداً واختباراً وتوثيقاً — ثم توقف.
المستودع: `https://github.com/cctw1382-stack/almas-elearning` — استعمل مهارة `almas-phase-controller`.
اللغة: تقارير بالعربية، كود وأسماء تقنية بالإنجليزية.

## 1) تحديد المرحلة (≤10 أوامر)

1. `git status --short --branch`، `git log --oneline -8`، `git fetch origin --prune`. لا تلمس تغييرات المالك المحلية.
2. اقرأ `AGENTS.md` + `docs/CODEX_STATE.md` (إن وُجد) + آخر سجل قبول. **لا تقرأ** `ALMAS_CODEX_MASTER_HANDOVER` أو `prototype/index.html` كاملين: `rg -n` ثم `sed -n` للمقاطع الضرورية.
3. إن كانت `PHASE = AUTO`: اختر **أول مرحلة غير مكتملة** وفق الأدلة (كود + اختبار + سجل قبول). ترقيم سجل التسليم قد يختلف عن `G0,P1…P6` في الـHandover؛ اكتب جدول مطابقة قصيراً في `docs/CODEX_STATE.md`، والكود الفعلي المختبر هو المرجع.
4. اكتب «عقد المرحلة» في `docs/CODEX_STATE.md` قبل أي كود: **الهدف**، **خارج النطاق**، **5–12 معيار قبول** قابل للاختبار (كل معيار = اختبار واحد على الأقل)، **المخاطر**.
5. إن كانت المرحلة المختارة تحتاج شيئاً لا يمكنك إنجازه (جهاز Android/TV، حساب خارجي، مفتاح، خادم) فنفّذ كل ما يمكن برمجياً، وسجّل الباقي `pending-human` أو `needs-owner`، **ولا تعتبره منجزاً**.

## 2) قواعد ثابتة

- **ممنوع بلا موافقة نصية جديدة:** دمج أي PR في `main`، نشر، أسرار/مفاتيح/دفع حقيقي، بيانات طلاب حقيقية، ترحيل على قاعدة إنتاج، `reset --hard`/`clean -fdx`/force-push، حذف اختبارات أو إضعاف توقعاتها، تعديل ملفات Hermes أو قراءة مفاتيحه.
- **قرارات لا تُمس:** هوية الماس و`docs/design-tokens.json`، `prototype/index.html` ملف واحد دون موارد خارجية (في مراحل HTML)، RTL، الأدوار الأربعة، سلوك الاختبارات القائمة، ستاك المستودع الفعلي (لا NestJS/Flutter دون قرار مالك).
- تعديلات **جراحية** (`karpathy-guidelines`): أقل تغيير يحقق المعيار؛ لا إعادة بناء شاملة.
- فرع مستقل `feat/<phase>-<اسم>` من أحدث نقطة سليمة، وcommit بعد كل مهمة صغيرة.

## 3) اقتصاد التوكن

- قصّ مخرجات الأوامر (`| tail -n 40`)، ولا تطبع diff كاملاً، ولا لقطات شاشة إلا لإثبات عيب بصري محدد.
- الاختبارات المتأثرة أولاً؛ المجموعة الكاملة `npm test` مرة واحدة عند الإغلاق.
- بلا وكلاء فرعيين متوازين. التفكير Medium؛ ارفعه فقط بعد 3 محاولات تصحيح منظمة فاشلة.
- حدّث `docs/CODEX_STATE.md` بعد كل commit. عند اقتراب حد الاستخدام: أنهِ المهمة الجارية، commit، اكتب «المهمة التالية الوحيدة»، توقف.


## 5) الاختبارات المطلوبة (اختر ما ينطبق على نوع المرحلة، وكلها إلزامية إن انطبقت)

| النوع | الحد الأدنى |
|---|---|
| منطق/بيانات | unit لكل دالة عامة جديدة + حالات حدّية + حالات خطأ؛ لا اختبار بلا assert حقيقي |
| واجهة | E2E على Chromium+Firefox+WebKit؛ عروض 360/768/1366؛ فاتح/داكن؛ لوحة مفاتيح وFocus؛ axe؛ لا طلب HTTP(S) خارجي؛ Refresh يحفظ الحالة؛ لا Overflow أفقي للصفحة |
| فيديو/امتحان | بدء/حفظ/تسليم مرة واحدة/انتهاء وقت/Refresh/إعادة صريحة؛ عدم تسرب حالة طالب لآخر؛ معاينة المعلم لا تغيّر حالة الطالب |
| API/DB | integration على DB مؤقتة؛ migrations up/down؛ **اختبارات سلبية للصلاحيات**: IDOR، عزل المدرسة/الولي، تلاعب `role` أو `childId` من العميل → رفض |
| أمان | حقن HTML/SQL، حدود الأحجام والمدخلات، rate limit، عدم تسريب أسرار في السجلات |
| انحدار | اختبار واحد على الأقل لكل عيب أُصلح (مرتبط بـ BUG-ID إن وُجد) |

قواعد: لا يُحسب الـSkip نجاحاً ويُذكر سببه؛ نتيجة قديمة لا تُنقل كأنها الحالية؛ إعدادات اختبار بيئية (مثل WebKit/file://) لا تُلغى لتمرير الاختبارات.

## 6) بوابة الإغلاق (كلها شرط — وإلا فالمرحلة «جزئية»)

- [ ] كل معيار قبول في العقد له اختبار يمر (أو `pending-human`/`needs-owner` موثق وصريح).
- [ ] اختبارات المتأثر + `npm test` الكاملة (+ اختبارات Go/DB إن وُجدت) نُفّذت **الآن** على HEAD النهائي، والنتائج مسجلة بأرقامها.
- [ ] CI على نفس الـSHA ناجح (رابط Run) — أو سبب موثق إن لم يتوفر.
- [ ] `review-agent` مرة واحدة على diff المرحلة، وأُصلحت النتائج الفعلية.
- [ ] سجل قبول المرحلة مكتوب في `docs/` بالأدلة (SHA + أوامر + نتائج + قيود)، و`CODEX_STATE.md` محدّث.
- [ ] PR مفتوح غير مدمج، واختيار «push + PR» عند `superpowers:finishing-a-development-branch`.
- [ ] لم تُعدَّل أسرار ولا Schema إنتاجي، ولم يُدمج أو يُنشر شيء.
