# قبول P6

| المجال | الحالة |
| --- | --- |
| فصل تشغيل الوسائط عن API | أضيف دور تشغيل مستقل ومهايئ ملفات محلي وإعداد Nginx. لم يُثبت توقف الوسائط داخل Compose. |
| توزيع API وفحص الصحة | إعداد نسختين ومسبح PostgreSQL بحد 8 اتصالات لكل عملية وفحص جاهزية بمهلة ثانية. نجح تجميع نقطة الدخول. |
| الفشل الجزئي | سكربت محلي يوقف خدمة الوسائط ونسخة API ويفحص الجاهزية من الموازن. التنفيذ يحتاج Docker. |
| قياس الحمل | سكربت مراحل لمحاكي HTTP، وليس مقياساً لقدرة Go أو PostgreSQL. |
| النسخ والاستعادة | نجح `infra/p6/backup-restore.ps1` بخروج 0، ونجحت فحوص PostgreSQL بعد الاستعادة إلى `almas_restore`. الدليل `.work/p6-restore.log`. |

نجح `infra/p6/load-stages.ps1` بخروج 0. هذه نتائج محاكاة HTTP محلية، وجميع أخطاء 4xx و5xx والاتصال صفر.

## بروفة الانتقال والرجوع

1. ثبّت SHA الصورة وإصدارات الترحيلات، وسجّل حالة الخدمات وقياسها قبل التغيير.
2. خذ نسخة PostgreSQL بصيغة custom عبر `pg_dump -Fc`، واحفظ نسخة مفاتيح كائنات الوسائط في التخزين الخاص. تحقّق من البصمات وإمكان فك النسخة.
3. استعد إلى قاعدة معزولة عبر `pg_restore --exit-on-error`. افحص الأدوار والترحيلات وعدد سجلات الاختبار ومحاولة امتحان ومسار HLS.
4. شغّل الوجهة بكتابة معطلة. اختبر الهوية والجاهزية وتوقف نسخة API أو خدمة الوسائط، ثم نفّذ الحمل المرحلي.
5. عند الموافقة على الانتقال الفعلي، أوقف الكتابة مؤقتاً، وانقل آخر نسخة، وتحقق من الوجهة قبل تحويل المرور. حدّد مسبقاً مدة التوقف المقبولة ونافذة الرجوع.
6. إذا فشلت الجاهزية أو ظهرت أخطاء تتجاوز الحدود المتفق عليها، أوقف الكتابة على الوجهة وأعد المرور إلى المصدر بعد تسوية أي كتابات حدثت على الوجهة. لا تستعد فوق قاعدة حية. احتفظ بالمصدر والنسخ حتى اعتماد الانتقال.

تتطلب البروفة `docker compose -f infra/p6/compose.yml up --build -d` بعد تجهيز قاعدة مؤقتة مُرحلة ومزوّد OIDC تجريبي قابل للوصول من الحاويات. ثم `pwsh -File infra/p6/check-failure.ps1`. خصص مفاتيح مؤقتة داخل بيئة التشغيل فقط. لا يغيّر أي سكربت DNS.
