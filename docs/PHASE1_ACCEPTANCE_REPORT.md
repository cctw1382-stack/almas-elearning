**القرار: اجتازت النسخة الحالية التشغيل المحلي الكامل: 20 اختبار بيانات و125 حالة متصفح ناجحة، مع تخطي واحد موثّق وصفر فشل. يبقى طلب الدمج مسودة، ولم تُغلق المرحلة الأولى.** الفحوص اليدوية معلّقة. يسجل التقرير التشغيل المحلي قبل النشر؛ حالة CI الحالية في [Actions لفرع الإصلاح](https://github.com/cctw1382-stack/almas-elearning/actions?query=branch%3Afix%2Fphase1-acceptance)، ولا يقرر هذا التقرير نتيجتها.

## نطاق المراجعة

نموذج [prototype/index.html](../prototype/index.html) في [فرع الإصلاح `fix/phase1-acceptance`](https://github.com/cctw1382-stack/almas-elearning/tree/fix/phase1-acceptance) المشتق من `feat/phase1-complete-ux`: ملف HTML واحد، CSS وJavaScript مضمّنان، بيانات تجريبية محلية، دون خادم أو إطار عمل. يشمل النطاق CRUD عبر مستودع محلي، ترحيباً ودخولاً تجريبياً، آخر محاولة امتحان محفوظة مع منع تعديل وحذف اختبار ذي محاولة، حالة درس مستقلة عن معاينات المعلم والإدارة، واختيار الابن وتخصيص المحتوى له. إعادة المحاولة تستبدل آخر نتيجة؛ لا يوجد أرشيف محاولات.

مرجع القبول: [المتطلبات](../REQUIREMENTS.md)، [SPECKIT](../SPECKIT.md)، [خطة الاختبار](ACCEPTANCE_TESTS.md)، و[الملاحظات التاريخية](PHASE1_REVIEW.md).

دور الطالب في هذا النطاق يمثل علي الوهمي (`u1`)؛ الأسماء المستعارة للعرض وليست هويات مستقلة. يمكن اختيار المشاركين في الواجبات والاختبارات عبر `studentIds` الاختيارية: بذور واجب الأحياء واختباره لعلي، وواجب الكيمياء لسارة. متابعة الابن الآخر لا تعرض نتيجة اختبار علي.

تسليمات الواجب محفوظة في `submissions` حسب معرّف الطالب. يكتب علي إجابته وحدها دون تعديل حالة عامة للواجب؛ متابعة سارة تعتمد إجابتها الخاصة ولا تكشف جواب علي أو حالة اكتماله في الواجب المشترك. تتحقق البيانات من صحة الخريطة، ويُمنع حذف طالب له تسليم مرتبط؛ قراءة النص القديم `submission` تخص `u1` فقط.

## نتائج التشغيل المحلي

المحركات من حزمة Playwright 1.59.1 المثبتة، وإصداراتها مطابقة لملف `playwright-core/browsers.json`. نتيجة كل صف تخص ملف HTML ذي البصمة أعلاه.

| النطاق | التغطية | نتيجة التنفيذ |
| --- | --- | --- |
| Node.js 22.23.2 | المستودع المضمّن في HTML، التخصيص والتسليم لكل طالب، حماية المحاولة، عزل المعاينات والتخزين | 20 ناجحاً، 0 فشل |
| Chromium 147.0.7727.15 | تدفقات الاستخدام و15 دورة CRUD والتواصل والامتحان والوسائط والتراجعات | 38 من 38 ناجحة، بما فيها الفيديو الأصلي |
| Firefox 148.0.2 | تدفقات الاستخدام نفسها والفيديو الأصلي | 38 من 38 ناجحة، بما فيها الفيديو الأصلي |
| WebKit 26.4 على Windows | تدفقات الاستخدام نفسها؛ استثناء محاكاة offline وفحص مستقل لقدرة الفيديو | 37 ناجحة و1 متخطاة للفيديو الأصلي، 0 فشل |
| Chromium بعرض 360 بكسل | صفحات قوائم الأدوار الأربعة، RTL والتجاوز الأفقي | 4 من 4 ناجحة |
| Chromium بعرض 768 بكسل | التغطية نفسها | 4 من 4 ناجحة |
| Chromium بعرض 1366 بكسل | التغطية نفسها | 4 من 4 ناجحة |
| أجهزة وفيديو يدويان | الصوت المسموع وملء الشاشة واللمس وAndroid وريموت الشاشة الذكية وقارئ الشاشة | لم يرفق دليل |

المجموع: 126 حالة Playwright = 38 لكل محرك + 12 حالة استجابة؛ 125 ناجحة و1 متخطاة و0 فشل. هذه الحالات مستقلة عن اختبارات المستودع العشرين.

التخطي الوحيد: أثبت فحص عنصر فيديو بسيط في صفحة منفصلة أن مفكك VP8 الأصلي لـ Windows WebKit غير متاح، مع الخطأ 4 (`MEDIA_ERR_SRC_NOT_SUPPORTED`) أو رفض `play()` بـ `NotSupportedError` رغم أن `canPlayType` يعلن `probably`. أُرفق ناتج JSON باسم `windows-webkit-native-media-probe`، وتُخطي الاختبار الأصلي وحده؛ تخطيه لا يثبت نجاح تشغيل الفيديو على المحركات الثلاثة. نجحت المحاكاة وعزل الأدوار وبقية حالات WebKit.

فتح `file://` في WebKit على Windows استخدم حظر HTTP(S) الصارم دون محاكاة offline بسبب قيد المحرك؛ أي طلب خارجي يفشل الاختبار، وتسجل ملاحظة بيئة في الحالات المتأثرة. احتاج تشغيل عملية الاختبار إلى الإطلاق خارج عزل أداة التنفيذ في هذه البيئة حتى يعمل Firefox؛ لم يُعطل عزل Firefox الداخلي. بعد ظهور قيد التنقل نفسه على Linux، أصبح إعداد WebKit يعطل محاكاة offline على جميع الأنظمة، مع بقاء حظر HTTP(S) وفشل الطلب الخارجي؛ يحتفظ Chromium وFirefox بمحاكاة offline. تخطي فك الفيديو الأصلي يظل خاصاً بـ Windows WebKit. تفاصيل السبب والعينة في [ملف العينات](../tests/fixtures/README.md).

## متابعة CI لبيئة الاختبار

ثُبت مشغل CI على Ubuntu 24 بعد عدم توافق بيئة Ubuntu 26 من `ubuntu-latest`. سجل [التشغيل 41197083464](https://github.com/cctw1382-stack/almas-elearning/actions/runs/41197083464) نجاح 18 اختبار مستودع و86 حالة متصفح، وفشل 37 حالة WebKit عند التنقل إلى `file://` قبل تهيئة التطبيق. أدى ذلك إلى تعميم تعطيل محاكاة offline لـ WebKit وحده، مع استمرار حظر HTTP(S) الصارم؛ لم يتغير ملف HTML أو بصمته. هذه نتيجة تشغيل سابق تفسر تعديل بيئة الاختبار، وليست ادعاء بنجاح التشغيل الأحدث؛ حالته تُراجع من Actions وطلب الدمج.

سجل [التشغيل اللاحق 41197455846](https://github.com/cctw1382-stack/almas-elearning/actions/runs/41197455846) نجاح 18 اختبار مستودع و122 حالة متصفح وفشل تأكيد الصوت بمقارنة `0.4000000059604645` بـ `0.4` حرفياً. عُدل التأكيد ليتحقق من التقارب بدقة خمس منازل، دون تغيير سلوك الصوت. بعد ذلك أضيف عزل تسليمات الطالب واختباراته؛ هذه النتائج السابقة لا تحل محل إعادة التشغيل على البصمة الحالية.

## إعادة إنتاج الفحص

من جذر المستودع مع Node.js وnpm:

```sh
npm ci
npx playwright install
npm test
```

يتطلب إعداد الاعتمادات والمتصفحات الشبكة. هذه أوامر الإعداد النظيف الموصى بها؛ التشغيل المحلي الحالي استخدم الاعتمادات المثبتة والمتصفحات المطابقة، ولم يُعد `npm ci`. تقارير Playwright المحلية في `playwright-report/`، وآثار الفشل في `test-results/` وفق الإعداد. رابط تشغيل CI المحدد ونسخة الالتزام ونتيجته تُراجع في طلب دمج فرع الإصلاح.

## حدود القبول

الدخول والمدفوعات والصلاحيات ومزودو الذكاء الاصطناعي محاكاة؛ لا توجد مصادقة إنتاجية أو حماية خادمية أو دفع حقيقي. لا يثبت هذا التقرير عزل المدارس أو أمان API أو النسخ الاحتياطية أو قدرة 1,000/10,000 مستخدم متزامن، ولا حماية الفيديو من النسخ.

القبول النهائي يتطلب مراجعة نتيجة CI للالتزام المنشور من الرابط أعلاه، واستكمال الفحوص اليدوية والمراجعة البشرية المطلوبة في SPECKIT، ومعالجة الفشل أو توثيق القيود التي تقبلها المراجعة. لا يغيّر النجاح المحلي وحده حالة PR أو يجيز دمج CI فاشل.
