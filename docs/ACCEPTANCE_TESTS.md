# اختبارات قبول المرحلة الأولى

النطاق: [نموذج HTML](../prototype/index.html) مستقل، عربي RTL، ببيانات محلية تجريبية. هذه خطة قبول؛ تفاصيل الدليل في [تقرير القبول](PHASE1_ACCEPTANCE_REPORT.md). نتيجة 2026-10-31 المحلية: 18 اختبار مستودع ناجحاً و122 اختبار متصفح ناجحاً وتخطٍ واحد للفيديو الأصلي في Windows WebKit، دون فشل. الفحوص اليدوية معلّقة؛ حالة CI الحالية في [Actions لفرع الإصلاح](https://github.com/cctw1382-stack/almas-elearning/actions?query=branch%3Afix%2Fphase1-acceptance) ولا يقررها سجل التشغيل المحلي.

## إعادة تشغيل الفحوص

من جذر المستودع مع Node.js وnpm، وثبّت المتصفحات قبل التشغيل الأول:

```sh
npm ci
npx playwright install
npm test
```

يحتاج تثبيت الاعتمادات والمتصفحات إلى الشبكة؛ تشغيل التطبيق نفسه يجب أن ينجح دونها. احتفظ بمخرجات التشغيل ونسخة الالتزام ومعلومات المتصفح وأي تقارير أو صور تنتجها الاختبارات. لا يُعتمد CI فاشل أو تشغيل جزئي على أنه اجتياز كامل.

شمل التشغيل المحلي Chromium وFirefox وWebKit عبر Playwright 1.59.1، وعروض Chromium البالغة 360 و768 و1366 بكسل. نجح تثبيت الاعتمادات والمتصفحات المطابقة؛ لم يُعد `npm ci` محلياً، ويُترك التحقق من الإعداد النظيف إلى CI. هذه نتائج متصفحات آلية على Windows وليست نتائج Android أو شاشة ذكية فعلية.

| الدرس والفيديو | تقدم المحاكاة، سؤال التوقف، الخطأ والصواب، ملاحظات وعلامات، تبديل الدرس والتحديث | استقلال الدرس والدور؛ المعاينة لا تغير حالة الطالب؛ بقاء مصدر الفيديو أثناء التفاعل |
| ولي الأمر | اختيار ابن ثم فتح درجاته وحضوره وواجباته واختباراته | بيانات الابن المختار ومحتوى مخصص له، دون إجراءات تسليم الطالب لولي الأمر |
| التواصل والإعدادات | رسالة فارغة وصحيحة، إشعارات، حفظ الملف والمظهر | خطأ واضح للفراغ وتغيير محلي ظاهر ومستمر للإجراءات الصحيحة |
| لوحة المفاتيح والإتاحة | التنقل والتركيز والتسميات والحوارات والمظهرين | عناصر مسماة وقابلة للتشغيل، تركيز ظاهر يعود إلى موضع مناسب، RTL صحيح |
| الاستجابة | عرض 360 و768 و1366 بكسل لكل دور والقوائم الطويلة | لا تجاوز أفقي للصفحة، وعناصر التحكم والمحتوى قابلة للاستخدام |

أي صف لا يغطيه اختبار منفذ يبقى فحصاً مطلوباً؛ وجوده في الجدول لا يثبت اجتيازه.

نطاق الهوية التجريبية: دور الطالب يمثل علي (`u1`) دائماً، والاسم المستعار يغير العرض فقط. `studentIds` تخصيص اختياري للواجب أو الاختبار يمكن تحريره من النموذج. لا ينبغي أن تظهر نتيجة علي عند متابعة الابن الآخر. يحتفظ كل اختبار بآخر محاولة فقط؛ إعادة المحاولة الصريحة تستبدل النتيجة السابقة ولا تنشئ أرشيفاً.

## ما تتحقق منه الاختبارات الآلية

التعريفات التالية تصف شفرة الاختبارات، ولا تعلن نتائج تشغيل. التقارير في `playwright-report/`، وآثار الفشل وصوره في `test-results/` وفق إعداد Playwright.

اختبارات [المستودع](../tests/repository.test.cjs)، بحسب ترتيبها؛ تستخرج الشفرة المضمّنة بين علامتي المستودع من HTML المرسل نفسه، وتفشل عند غيابها:

| الاختبار | ما يفحصه |
| --- | --- |
| بيانات البداية والقراءات المنفصلة | وجود مجموعات الأدوار ومعرّفات نصية، وعدم تعديل المخزن عبر تغيير قيمة مقروءة متداخلة |
| حفظ دورة CRUD وسجل العمليات | الإنشاء والتعديل والحذف بعد إعادة إنشاء المستودع، وتسجيل التغيير مرة واحدة دون تكرار سجل العمليات لنفسه |
| العلاقات والإدخال غير الصالح | منع حذف مادة مرتبطة ورفض مجموعة غير صالحة وأسماء وتفاصيل وقيم وعلاقات مخالفة |
| إعدادات JSON | استمرار قيم الإعدادات دون مشاركة المراجع، ورفض مفاتيح وقيم غير صالحة |
| تخصيص الواجبات والاختبارات | حفظ قائمة الطلاب الاختيارية `studentIds`، ومنع المعرفات المجهولة والمكررة والأنواع المخالفة |
| حذف الطالب المرتبط | منع حذف طالب مرتبط بتخصيص واجب أو اختبار، والسماح بعد إزالة الارتباط |
| استقلال حالات الدروس | حفظ تقدم وثوان وملاحظات وعلامة وإجابة نقطة توقف لكل درس، ورفض القيم المخالفة |
| استمرار محاولة نشطة | بقاء الإجابات وعلامات المراجعة والسؤال الحالي والموعد دون تمديد الوقت |
| عزل معاينات الأدوار | استقلال حالة الطالب والمعلم والإدارة للدرس نفسه وعبر إعادة إنشاء المستودع، ورفض نطاق غير صالح |
| التقديم اليدوي | صحة درجة إجابات معلومة وثبات النتيجة بعد التقديم |
| انتهاء الوقت | تصحيح محاولة منتهية عند قراءتها وحفظ النتيجة دون إعادة التصحيح |
| إعادة المحاولة الصريحة | عدم مسح نتيجة عند عرضها، وبدء أجوبة ووقت جديدين فقط عند طلب إعادة المحاولة |
| تعديل اختبار له محاولة | رفض تعديل الأسئلة أو العنوان بعد بدء المحاولة وبعد التقديم مع ثبات الدرجة |
| حذف اختبار له محاولة | رفض الحذف لمحاولة نشطة أو مقدمة، والسماح بحذف اختبار جديد بلا محاولة |
| تخزين تالف | استخدام بذور وذاكرة صالحتين مع تحذير عند JSON أو بنية مخزنة غير صالحين |
| التخزين الممنوع أو الممتلئ | استمرار التغيير في ذاكرة الجلسة وإتاحة تحذير بدلاً من إسقاط التفاعل |

| بيانات البداية الحساسة | البحث عن الحقول والأنماط الحساسة المحددة في بذور التجربة؛ ليس تدقيق أسرار شاملاً |

## قيود بيئة الاختبار

- على Windows، يرفض WebKit فتح ملفات `file://` عند تفعيل محاكاة offline حتى لصفحة بسيطة؛ يعطل الإعداد هذه المحاكاة لهذا المحرك على Windows فقط. يبقى اعتراض HTTP(S) وحظره وإفشال الاختبار عند محاولته فعالاً، وتسجل ملاحظة بيئة في تقرير كل اختبار متأثر. Linux وبقية المحركات تحتفظ بإعداد offline.
- اختبار الفيديو الأصلي على Windows WebKit يسبق صفحة المنتج بفحص مستقل لعنصر فيديو بسيط. يُرفق ناتج JSON، ويُتخطى هذا الاختبار وحده إذا أثبت الفحص الخطأ 4 أو `NotSupportedError`. لا تكفي قيمة `canPlayType` للحكم؛ فشل التطبيق أو أي خطأ آخر يظل فشلاً. لا يُطبق هذا التخطي على بقية المحركات أو Linux، وتعمل المحاكاة وعزل الأدوار على الجميع.
- تشغيل عملية اختبار Firefox في بيئة Windows الحالية يتطلب الإطلاق خارج عزل أداة التنفيذ؛ هذا قيد بيئة التشغيل ولا يعني تعطيل عزل Firefox الداخلي أو نجاح الاختبارات.
- عينة الفيديو صامتة: ضبط قيمة الصوت آلياً لا يثبت سماعه، ولا تثبت الاختبارات ملء الشاشة الأصلي. التخطي ليس نجاحاً، ونجاح المحاكاة ليس دليلاً على تشغيل فيديو فعلي.

تفاصيل العينة وتجارب العزل في [ملف العينات](../tests/fixtures/README.md). سجل [تقرير القبول](PHASE1_ACCEPTANCE_REPORT.md) نتيجة التشغيل النهائي المحلي: تخطي أصلي واحد لـ Windows WebKit، دون احتسابه نجاحاً.

## فحوص يدوية لا يكفي لها المتصفح الآلي

- اختر فيديو صالحاً من الجهاز: تشغيل وإيقاف، تقديم وتأخير، سرعة، صوت وكتم، ملء الشاشة والخروج منه. تحقق من بقاء المصدر والوقت بعد حفظ ملاحظة أو علامة وإجابة سؤال؛ أعد اختيار الملف بعد تحديث الصفحة وتحقق من الاستئناف.
- جرّب رفض نوع ملف غير مناسب وتعذر تشغيله. تحقق من أن المحاكاة تظل متاحة دون ملف فيديو.
- على Windows وAndroid حقيقيين: اللمس ولوحة المفاتيح، تغيير الاتجاه، لوحة المفاتيح الافتراضية، تشغيل الصوت وملء الشاشة وفق قيود المتصفح.
- على شاشة ذكية فعلية: أسهم الريموت وOK والرجوع وظهور التركيز والوصول إلى القوائم والمشغل. تغيير أبعاد متصفح الحاسوب ليس اختبار شاشة ذكية.
- افحص قارئ الشاشة والتباين ووضوح رسائل الخطأ وحالات الفراغ، وأعد التجربة عند منع التخزين المحلي.

سجّل نوع الجهاز ونظامه والمتصفح وتاريخه والخطوات والنتيجة لكل فحص يدوي. لا تعلن دعم جهاز لم يُختبر.

## بوابة القبول وما يؤجل للإنتاج

يبقى طلب الدمج مسودة إلى أن تُسجّل الأدلة وتُراجع الثغرات الباقية. لا تُغلق المرحلة الأولى لمجرد نجاح تثبيت الاعتمادات أو إنشاء الاختبارات؛ لا تُدمج تغييرات CI الفاشلة. تطبق مراجعة [SPECKIT](../SPECKIT.md) على تغييرات auth/billing/permissions/schema/backup.

الإنتاج يحتاج اختبارات مستقلة لعزل الطلاب والمدارس وRBAC وIDOR وأمان API وترحيلات البيانات واستعادة النسخ الاحتياطية. يلزم سيناريو حمل وتوزيع طلبات وبث وقياسات p95 وCPU/RAM/DB IO قبل ادعاء 1,000 جلسة متزامنة، ثم إعادة القياس قبل ادعاء 10,000. المحاكاة المحلية للمدفوعات والصلاحيات لا تثبت أمان هذه الخدمات.
