# منصة الماس للتعليم الإلكتروني | Almas E-Learning

نموذج تعليمي عربي RTL للأدوار الأربعة: الطالب والمعلم وولي الأمر والإدارة. يعمل التطبيق من ملف [prototype/index.html](prototype/index.html) واحد يحوي HTML وCSS وJavaScript وبيانات تجريبية، دون خادم أو إطار عمل.

**حالة القبول: نجح التشغيل المحلي؛ الفحوص اليدوية معلّقة، وطلب الدمج يبقى مسودة. لم تُغلق المرحلة الأولى.** النتيجة: 18 اختباراً وحدياً ناجحاً، و122 اختبار متصفح ناجحاً مع تخطي اختبار فيديو أصلي واحد في WebKit على Windows. هذا سجل محلي؛ تُراجع حالة CI الحالية في [Actions لفرع الإصلاح](https://github.com/cctw1382-stack/almas-elearning/actions?query=branch%3Afix%2Fphase1-acceptance). راجع [تقرير القبول](docs/PHASE1_ACCEPTANCE_REPORT.md) و[المراجعة](docs/PHASE1_REVIEW.md).

## تجربة النموذج محلياً

1. نزّل المستودع وافتح `prototype/index.html` في متصفح حديث؛ عرض الملف على GitHub لا يشغّل التطبيق.
2. من الترحيب اختر الدخول أو التسجيل التجريبي أو المتابعة كضيف، ثم جرّب الدور المطلوب.
3. تنقّل بين الأقسام وجرّب البحث والفلاتر والتفاصيل وتبديل المظهر.

لا يحتاج تشغيل النموذج بعد تنزيله إلى npm أو إنترنت. تثبيت أدوات الاختبار والمتصفحات يحتاج اتصالاً عند إعداد بيئة الاختبار أول مرة.

## نطاق التجربة المحلية

- الطالب: مواد ودروس، فيديو محلي أو محاكاة، أسئلة توقف، ملاحظات وعلامات وتقدم لكل درس، اختبار بمؤقت ومراجعة ونتيجة، واجبات ورسائل وإشعارات وإعدادات تجريبية.
- المعلم والإدارة: إضافة السجلات وعرضها وتعديلها وحذفها محلياً، مع التحقق من الإدخال والبحث وتحديث القوائم؛ تتعامل الواجهات مع مستودع بيانات تجريبي عبر مزود البيانات. معاينات الفيديو تحفظ ملاحظات وتقدم كل دور مستقلاً عن حالة الطالب.
- ولي الأمر: اختيار الابن وعرض درجاته وإنجازه وحضوره، وتصفية الواجبات والاختبارات حسب الطالب المخصص لها.
- تُحفظ بيانات التجربة ومحاولات الاختبار وحالة الدروس في المتصفح. يستمر موعد انتهاء الاختبار عند تحديث الصفحة؛ لا يتوقف مرور الوقت بمغادرة الشاشة.

توضح [اختبارات القبول](docs/ACCEPTANCE_TESTS.md) السلوكيات التي تتحقق منها الأتمتة والفحوص اليدوية الباقية. نتائج التشغيل المحلي وحدود التغطية مسجلة في تقرير القبول.

يحتفظ النموذج بآخر محاولة لكل اختبار، وليس بأرشيف المحاولات. إعادة الاختبار الصريحة تستبدل المحاولة والنتيجة السابقتين. يُمنع تعديل أو حذف اختبار له محاولة نشطة أو مقدمة لحماية الإجابات والنتيجة المحفوظتين.

دور الطالب يمثل الطالب الوهمي علي (`u1`)؛ اسم الدخول المستعار للعرض فقط ولا ينشئ هوية طالب أخرى. يمكن تحديد المشاركين في نموذج الواجب أو الاختبار بقائمة `studentIds` الاختيارية. في بيانات البداية، واجب الأحياء واختباره لعلي، وواجب الكيمياء لسارة؛ متابعة سارة لا تعرض نتيجة اختبار علي.

ملف الفيديو المختار يبقى على جهازك. عند إعادة فتح الصفحة قد يلزم اختياره مجدداً لاستعادة موضع المشاهدة؛ لا يُحفظ ملف الفيديو نفسه. التخزين المحلي مرتبط بالمتصفح وموقع الملف؛ حذف بيانات المتصفح أو منع التخزين قد يفقد التغييرات. استخدم بيانات وهمية فقط.

## تشغيل الاختبارات

من جذر المستودع، بعد توفير Node.js وnpm:

```sh
npm ci
npx playwright install
npm test
```

توضح [خطة القبول](docs/ACCEPTANCE_TESTS.md) السيناريوهات المطلوبة والفحوص اليدوية. لا تُنسب نتائج إلى متصفح أو عرض شاشة أو جهاز إلا بعد تسجيل دليل تشغيله. تستخدم الاختبارات Node.js وPlaywright كأدوات تطوير؛ التطبيق نفسه يظل ملف HTML مستقلاً.

التشغيل المحلي في 2026-10-31 استخدم Playwright 1.59.1: Chromium وFirefox وWebKit، مع 12 فحص تنقل واستجابة على Chromium بعروض 360 و768 و1366. ثُبتت الاعتمادات والمتصفحات المطابقة محلياً؛ الأمر `npm ci` أعلاه مسار الإعداد النظيف ولم يُعد تشغيله محلياً. حالة التحقق منه تُقرأ من تشغيل CI المرتبط بالالتزام.

تفاصيل قيود بيئة Windows وفحص قدرة تشغيل الفيديو موضحة في [ملف عينات الاختبار](tests/fixtures/README.md). تجاوز محاكاة offline في WebKit على Windows يبقي حظر وفشل أي طلب HTTP(S) فعالاً. التخطي المشروط لاختبار الفيديو الأصلي لا يُحسب نجاحاً لتشغيل الفيديو.

## حدود المحاكاة

الدخول وتبديل الأدوار والصلاحيات والاشتراكات والمدفوعات ومزودو الذكاء الاصطناعي محاكاة محلية. لا توجد مصادقة أو حماية وصول أو مدفوعات أو خدمة AI إنتاجية. لا تدخل كلمة مرور حقيقية أو مفتاح API أو بيانات دفع أو بيانات قاصرين. التقارير تعليمية، ولا توجد حماية تمنع نسخ الفيديو أو شهادة أداء لآلاف المستخدمين.
